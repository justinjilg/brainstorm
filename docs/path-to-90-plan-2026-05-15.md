# Path-to-90 Remediation Plan — 2026-05-15

Goal: every stochastic-assessment dimension ≥ 9.0 ("above 90"). No new
features until threshold. All work through PR flow, Codex-reviewed, verified
with citations.

**Baseline:** v13 (2026-04-19) Overall 6.10/10. v14 partial (4 of 10
assessors complete at time of plan): Optimist 6.83, Pessimist 5.85, Architect
6.10, Auditor 5.30. v14 mean gap to 9.0 is ~3.0 points/dim.

## Convergent signals (named by ≥3 of 4 v14 assessors so far)

1. **Envelope drop** — 25 of 33 live `x-br-*` headers discarded by the hot-
   path provider `packages/providers/src/cloud/brainstorm-saas.ts`. Hits D1,
   D2, D5, D6, D8 simultaneously.
2. **BR endpoint coverage shallow** — 20 of 144 documented endpoints consumed
   (~14%). D1, D2.
3. **Zero live BR contract tests** — drift is detected only when a human
   audits (PR #302 was hand-driven). D3.
4. **README + CLAUDE.md package drift** — claim 27, actual 45 (67% drift).
   D7.
5. **Audit-hash chain never persisted** — `x-br-audit-hash` arrives, drops.
   The "governed channel" claim has no auditable artifact. D5, D6.
6. **Agent never claims an `agent_id`** — community key only; `/v1/self`
   returns `agent_id: null`. D6.
7. **`/v1/discovery` cached but not consumed by the router** — strategies
   hardcoded under `packages/router/src/strategies/`. D2.
8. **No CHANGELOG.md** — PR descriptions are the change log. D7.
9. **Production telemetry near zero** — 12 npm downloads/week, last publish
   2026-04-03 (42 days stale). D4.
10. **Scale: single-instance, per-session** — SQLite at
    `~/.brainstorm/brainstorm.db`, no daemon, no shared-state story. D9.

## Strategy: locality-grouped ratchets

Each phase produces (a) a measurable lift on the targeted dimension(s), and
(b) a CI ratchet that prevents the same regression class from recurring.
Phases group by code locality where possible (per
[feedback_full_refactor_over_staged] + [regroup-by-locality]). Each phase is
1–5 PRs.

The phase order matches gap × leverage × dependency. Phase 1 unblocks
Phase 2, etc.

## Phase 1: BR envelope consumption + ratchet (1 PR)

**Targets:** D1 (claimed→real), D2 (wiring), D5 (operability),
D6 (security/provenance — partial), D8 (failure-signal use).

**Scope:**

1. New file `packages/providers/src/cloud/br-envelope.ts`: typed
   `BrEnvelope` interface + `parseBrEnvelope(headers: Headers): BrEnvelope`
   covering all 33 live `x-br-*` headers.
2. Wrap the SaaS provider's fetch with envelope-capture middleware that
   emits a `br-envelope` event on every response.
3. Wire the event through `useRoutingStream` into `DashboardMode.tsx` (new
   panel rows: routed-model, route-confidence, quality-tier,
   reputation-tier, routing-savings, deprecation, audit-hash short).
4. **Ratchet:** a new test `packages/providers/src/__tests__/br-envelope-coverage.test.ts`
   that lists the canonical 33 headers. CI fails if BR's live response
   contains a header not in the list (drift detection) OR if a header in
   the list has no typed field on `BrEnvelope` (unparsed-signal detection).

**Verification:** turbo build green; new test passes against live BR
response; manual `storm chat "ping"` shows routed-model + cost in dashboard.

**Estimated lift:** D1 +0.5, D2 +1.0, D5 +0.3, D6 +0.4, D8 +0.5.

## Phase 2: Audit-hash persistence + trajectory chaining (1 PR)

**Targets:** D5 (operability — auditable history), D6 (security — actual
provenance chain), D8 (failure traceability).

**Scope:**

1. New SQLite table `routing_audit` keyed on `(request_id, audit_hash)`
   with columns for envelope fields (routed_model, cost, latency, reasoning
   JSON, guardrail_status, audit_hash, timestamp).
2. Migration in `packages/db/src/migrations/` + repository at
   `packages/db/src/routing-audit-repository.ts`.
3. Hook into Phase-1 envelope event: persist on every chat turn.
4. Update `packages/core/src/plan/trajectory-capture.ts` to include the
   captured audit hashes per phase, so trajectories submitted via
   `IntelligenceAPIClient.submitTrajectory()` (POST /v1/agent/trajectory)
   carry BR's chain.
5. **Ratchet:** test that asserts every persisted audit-hash chain is
   continuous (no orphans).

**Verification:** after a multi-turn chat, `SELECT * FROM routing_audit
ORDER BY ts DESC LIMIT 10` shows continuous hash chain; trajectory JSONL
includes `br_audit_hashes[]`.

**Estimated lift:** D5 +0.5, D6 +0.7, D8 +0.5.

## Phase 3: Agent identity (1 PR)

**Targets:** D6 (per-agent accountability), D2 (proper bootstrap path).

**Scope:**

1. Call `POST /v1/agent/bootstrap` on first run when no `agent_id` is
   stored locally. Persist returned `agent_id` and `agent_jwt` to vault.
2. Switch chat completion auth path to use the agent JWT when available,
   falling back to the community key only when bootstrap fails AND user
   explicitly opted into community mode.
3. Surface the agent identity in `storm status` + `ConfigMode.tsx`.
4. **Ratchet:** a test that asserts a fresh install path produces an
   `agent_id` matching the BR `/v1/self.identity.agent_id` shape.

**Verification:** `storm status` shows a real `agent_id` (UUID); `GET
/v1/self` returns non-null `agent_id`; reputation tier becomes per-agent.

**Estimated lift:** D2 +0.3, D6 +0.6.

## Phase 4: Discovery as runtime contract source (1 PR)

**Targets:** D1 (claimed features real), D2 (wiring), D3 (drift detection).

**Scope:**

1. Cache `/v1/discovery` result at startup with 24h TTL into SQLite.
2. Router strategy enumeration reads from the cache, falls back to
   hardcoded list only if discovery is unreachable AND no cached value
   exists.
3. Memory block validation in `br-intelligence.ts` reads block names from
   discovery rather than the hardcoded enum (which PR #302 already aligned
   but is still hardcoded).
4. **Ratchet:** test that asserts the hardcoded fallback list ⊆ live
   `/v1/discovery` response (catches BR side adding strategies without
   us noticing).

**Verification:** removing a strategy from the local list works because
discovery still has it; adding a new strategy to BR makes it auto-appear.

**Estimated lift:** D1 +0.4, D2 +0.6, D3 +0.3.

## Phase 5: Live BR contract test in CI (1 PR)

**Targets:** D3 (test reality — the ratchet for everything Phase 1–4 enabled).

2. Fetches `/openapi.json` + `/v1/discovery` + does one
   `POST /v1/chat/completions` with the community key.

**Verification:** introduce a deliberate drift (e.g., rename a path in
`packages/gateway/src/client.ts`) → CI fails with a precise message.

**Estimated lift:** D3 +1.5.

## Phase 10: Scale infrastructure — DECISION GATE

**Targets:** D9 (scale readiness).

This phase is **gated on a structural decision Justin makes**: should
brainstorm-CLI grow a daemon mode + shared-state path (multi-session,
multi-user)? Or is the per-session SQLite the deliberate posture?

If per-session is the deliberate posture, D9 has a structural ceiling
around 6–7 (the rubric rewards multi-instance + load-tested + shared
state). To reach 9.0 on D9, a daemon mode is required.

**Recommendation: defer.** This is the only phase that requires Justin's
direct call. We can hit ~7 on D9 with documented intent ("the per-session
posture is intentional for CLI; ChangeSet execution is the multi-instance
surface and lives in BR"), but 9.0 requires structural change.

Action without sign-off: surface this as an explicit "Open Questions"
entry in CLAUDE.md so a fresh-perspective contributor sees it.
